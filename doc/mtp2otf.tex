\section{Overview}
mtp2otf converts MathTime\texttrademark{} Professional 2 (MTPro2) Type~1
fonts and TeX metrics to OpenType MATH. It preserves the source designs,
including optical script sizes, and supplies the layout
data used by Unicode math engines. Upright Latin letters and additional
text characters come from a separate Roman font pair.

The converter produces OTF for LuaLaTeX and TTF for Windows.
Full and Lite use separate family names and can be installed together.
The selected edition requires the corresponding MTPro2 source files.

No additional mtp2otf package is needed to use the generated fonts.
Unicode characters and OpenType features provide access to the designs.
The original \file{mtpro2} package's custom commands are not included.
See \file{mtp2otf-guide.pdf} for illustrated font usage and character variants.

\section{Building the fonts}\label{sec:build}
\subsection{Requirements}
The build requires a POSIX shell, Python~3.10 or later with fontTools,
FontForge with Python~3.10 or later support, and \file{tftopl} from
TeX Live. These commands must be on PATH.

Create \file{mtpro2/} and \file{donors/} beside \file{build.sh}.
Supply the font files separately:
\begin{itemize}
\item \file{mtpro2/}: MTPro2 PFB/TFM files and \file{mtpro2.sty}.
Full also requires \file{umt2ms.fd}, \file{umt2mf.fd},
\file{umt2bb.fd}, and \file{umt2hrb.fd}.
\item \file{donors/}: \file{NimbusRoman-Regular.otf} and
\file{NimbusRoman-Bold.otf} from Artifex urw-base35.
\end{itemize}
Place the files directly in these directories. The build reports missing
inputs for the selected edition.

Another Roman pair can be selected with the options below. The faces must
be static CFF OTF or TrueType TTF, upright and proportional, from the same
family, and have the required Latin and digit coverage and Regular/Bold
weights.

\subsection{Build options}
The default build uses Full and minimal donor coverage:
\begin{samepage}
\begin{verbatim}
./build.sh
\end{verbatim}
\end{samepage}
Select Lite, extended donor coverage, or a different Roman pair as needed:
\begin{samepage}
\begin{verbatim}
./build.sh --edition=lite
./build.sh --donor-coverage=extended
./build.sh --roman-regular=/path/to/Regular.otf \
           --roman-bold=/path/to/Bold.otf
./build.sh --help
\end{verbatim}
\end{samepage}
The edition and donor options can be combined. Relative donor paths are
resolved from the current directory; project paths are relative to
\file{build.sh}.

Minimal coverage uses a fixed selection of Roman characters. Extended
coverage adds eligible characters available in the Regular donor, without
replacing MTPro2's mathematical glyphs. It does not add Full-only features
to Lite. Appendix~\ref{sec:donors} lists the selection rules.

\subsection{Output}
The generated fonts are placed in \file{out/}:
\begin{center}
\begin{tabular}{@{}lll@{}}
\toprule
Edition & OTF & TTF \\
\midrule
Full & \file{MTPro2Math.otf} & \file{MTPro2Math.ttf} \\
Lite & \file{MTPro2MathLite.otf} & \file{MTPro2MathLite.ttf} \\
\bottomrule
\end{tabular}
\end{center}
Install the generated fonts manually. Errors are reported on stderr;
generation diagnostics are recorded in \file{build/<edition>/build.log}.
Check the command's exit status: a failed build may leave previous output
files in place. Do not run concurrent builds of the same edition.

\section{Using the fonts}\label{sec:use}
\subsection{Microsoft Word}
Install the TTF and select \file{MTPro2 Math} or
\file{MTPro2 Math Lite} as the equation font. For the equation text,
enable \emph{Kerning for fonts} at 1~pt and above in the Font dialog.
Ordinary mathematical characters include the source italic correction
in their advances, so their spacing does not depend on Word adding it
between letters. Ordinary pair kerning remains separate. Script placement
and the width of a completed formula still depend on the equation engine;
see Appendix~\ref{sec:scalars}.

Use Word's equation editor for mathematical alphabets, accents, delimiters
and operators. It does not expose the same OpenType feature controls as
LuaLaTeX. The explicit feature examples in \file{mtp2otf-guide.pdf} are for LuaLaTeX.

Large operator selection depends on the equation's growth setting.
In the Microsoft 365 Word examples checked on 25 October 2026,
ordinary sums, products and integrals remained at display size even with
tall operands or limits. Enabling n-ary growth selected the XXL designs
for the three matrix examples. This does not establish access to every
size or character variant in Word.

\subsection{LuaLaTeX}
Load the OTF with \file{unicode-math}:
\begin{samepage}
\begin{verbatim}
\usepackage{unicode-math}
\setmathfont{MTPro2Math.otf}
\end{verbatim}
\end{samepage}
For Lite, use \file{MTPro2MathLite.otf}. If the font is not installed,
specify its directory with the \file{Path} option.

Use \file{unicode-math} commands for alphabets and symbols, and the usual
math structures for scripts, fractions, accents and delimiters.
See \file{mtp2otf-guide.pdf} for input examples and visual comparisons;
Appendix~\ref{sec:alphabets} lists the exact feature inputs.

Luaotfload 3.29 can omit pair kerning between script-size variants.

The font can also be used with \file{lua-unicode-math}.

The engine compares its size request with MATH AdvanceMeasurement.
This is a selection dimension and need not equal the glyph's ink extent.
The 27 extended operator series have text/display and four additional
ready-made designs (xl, XL, XXL, XXXL), with no repeatable assembly.
Normal text/display selection and all MATH constants remain unchanged.
With ordinary \file{unicode-math} input, the height of a following
expression does not enlarge an operator. A larger design can be selected
by an explicit LuaTeX size request; see \file{mtp2otf-guide.pdf}.
Word controls these requests through its equation settings.
Bigcupdot (U+2A03) retains its two designs.
Default parentheses, braces and radicals use the ordinary source sequence;
\file{cv07}/\file{cv08} select larger delimiter series.

\subsection{Angle brackets and vertical bars}
The small sizes of angle brackets and vertical bars need a common size
sequence. In the original conversion, the angle brackets had five finite
sizes, while single and double bars had only their base size followed by
an assembly. Comparing automatic delimiters with Latin Modern Math showed
that a bar could remain visibly shorter than the adjacent angle brackets
around the same expression. Latin Modern provided a reference for closer
small-size steps, rather than outlines to copy.

The source and output use different growth mechanisms. Traditional TeX
uses the TFM next-larger chain and extensible recipes; part placement is
based on TFM box dimensions. OpenType MATH supplies size measurements,
part advances and connector lengths, and lets the layout engine vary
connector overlap within those limits. Thus, translating the source
outlines does not by itself reproduce the Type~1 assembly heights.
For the source bar extension parts, the TFM height plus depth is about
600 font units, whereas the outline spans 636. The source's repeated
placement therefore gives about 36 units of outline overlap. This is
not the same quantity as MATH's minimum connector overlap, which is 20
in the final font. With only a few parts, a difference in placement or
size selection is a larger fraction of the total height and is more
noticeable than in a tall assembly.

To give small delimiters more consistent choices, v1.5 adds three
intermediate angle sizes and seven finite sizes to each bar series.
The resulting eight stages are shared by the left and right angle
brackets, single bars and double bars in both editions:

Values are in font units at 1000 units per em. The new 1100, 1450 and
2100 stages follow the corresponding Latin Modern angle sizes, while
retaining all five source angle designs. The bars follow this adopted
angle sequence, not Latin Modern's separate bar sequence.
AdvanceMeasurement is the ceiling of the ink height plus one unit;
it is the selection measurement, not the horizontal advance width.

New angle outlines interpolate corresponding vertices and advance widths
between adjacent source designs after aligning their vertical centers.
This retains the source designs at their original sizes and avoids simply
stretching one angle vertically. New bar outlines use the source
extension part's horizontal coordinates and advance: each stroke is
45 units wide, with a 103-unit inner gap in the double bar.
The original base bars are retained.

Each added bar matches both the lower and upper ink bounds of the
corresponding angle, not just its total height. LuaTeX rounds height and
depth separately in script and scriptscript styles; matching only their
sum can select different stages at a size boundary.
The relation inputs U+2223 and U+2225 share the finite size lists of
U+007C and U+2016 respectively. The implementation is
\file{build_angle_bar_sizes} in \file{tools/font_geometry.py}.

This addition leaves the existing bar assembly records intact. Bars can
still grow beyond the largest finite size, whereas angle brackets have
no assembly and stop at the 3000-unit design. The shared sequence improves
small-size selection; it does not guarantee equal heights for every
expression, application or size request.

\section{Metrics and MATH constants}\label{sec:scalars}
\subsection{Glyph metrics}
The output uses 1000 units per em. For ordinary mathematical characters,
let $W$ and $I$ be the separately rounded integer source width and italic
correction before the final advance conversion. The final values are
\[
  \text{advance}=W+I,\qquad
  \text{MATH IC}=0,\qquad
  \text{BottomRight MathKern}=-I.
\]
The right-lower kern is constant at every height; the other three corners
are unset. Glyphs with zero correction retain their metrics without a
redundant zero-kern record. The sum uses the existing integers, rather
than rounding the raw TFM sum again.

This policy covers the mathematical alphabets, including Script, Fraktur
and Blackboard, their optical sizes and alternate designs. It also covers
ordinary nabla, bold nabla and partial differential, and the AMS yen
alternative where the edition supplies them. Each physical glyph uses its
own source correction. The correction is not inferred from whether the
outline looks italic or from its Unicode category alone.

The source TeX spacing for an ordinary character includes its italic
correction. Storing that effective width as the advance makes it available
to engines that do not add the correction between ordinary letters.
The superscript reference $W+I$ is retained; the subscript reference
returns to $W$ when the engine applies the right-lower kern.
Dedicated integrals, sums and products retain their separate metrics and
italic corrections, including the corrections used to position limits.
Their existing conversion may already include source italic correction
in the advance. Delimiters, assemblies, accents and primes retain their
own construction and placement rules.

Ordinary GPOS pair adjustments store the TFM pair kern without an added
italic-correction term. Skewchar pairs are excluded from ordinary
kerning. Top-accent attachment for source math alphabets is based on
\[
  \frac{\operatorname{CHARWD}+\operatorname{CHARIC}}{2}
  + \operatorname{skewkern}.
\]
For untransformed source alphabets, this calculation uses the exact TFM
fixed-point values and is rounded once to output units. Its absolute
coordinate is retained when the advance is changed; it is not recomputed
from the new advance or zero MATH IC. Combining accents and synthesized
forms use the corresponding coordinate transformations and geometric
attachment positions. Primes retain their dedicated conversion.
Text, script and scriptscript designs use the source optical sizes.

\paragraph{Engine-dependent limits.}
LuaHBTeX~1.24 can omit MathKern when a subscript starts with a fraction,
radical, explicit box or unsupported structure, or uses a font without
MATH support. An explicit style at the start or an empty subscript can
also change the path used by the engine. Such a subscript may move right
by the original $I$; a single visible letter does not guarantee that the
kern is used. Converting an ordinary character into an operator with
\file{\mathop} also cannot recover its former limit correction.
These cases do not change the dedicated operator data or call for an
additional pair-kerning adjustment.

Preserving the subscript origin does not always preserve the completed
box width. An engine that includes the base advance in the maximum of
component widths changes that term from $W$ to $W+I$. For a subscript
of width $S$ and trailing script space $s$, the width is preserved when
$S+s\ge I$. A narrow subscript on a large-correction glyph can therefore
increase the box width; this is not restricted to Script alphabets.
For example, a 10\,pt Script T with a dot subscript gives a 0.365\,pt
increase under this maximum-width rule, although the subscript origin is
unchanged. This is a reference calculation, not a Word measurement.
Similarly, retaining accent attachment coordinates does not guarantee
that an engine selects the same width of stretching accent.

\subsection{Constants}
The following assignments define the 56 MATH constants and the common
connector overlap in both editions. They combine source metrics, package
script ratios and conversion policies.

The expressions follow \file{tools/native_math.py} in evaluation order.
\texttt{round} uses nearest-integer rounding, ties to even; \texttt{//} is
floor division and \texttt{Fraction(a,b)} is exact rational arithmetic.
Intermediate rounding is part of each assignment.

\texttt{upm} is the output units per em. \texttt{s(i)} is
\texttt{round(sy[i] * upm)}, with \texttt{sy} from \file{mt2syt.tfm};
\texttt{e(i)} uses \file{mt2exa.tfm}. \texttt{theta = e(8)} and
\texttt{xh = s(5)}. \texttt{script\_sy} comes from \file{mt2sys.tfm}.

The script ratios are the \file{mtpro2.sty} defaults;
\texttt{\_pct(r)} is \texttt{round(r.numerator * 100 / r.denominator)}.

\texttt{display\_operator\_min\_height} is computed from the 30 mapped
text/display operator pairs in \file{mt2exa.tfm}. Round each height-plus-depth
to output units, then take
\texttt{(max(text sizes) + min(display sizes)) // 2}.
The source values give \texttt{(1103 + 1203) // 2 = 1153}.
The delimited-subformula threshold uses the same value. This is a conversion
policy; TFM box dimensions and OpenType glyph bounds need not select the
same design in every series.

\texttt{cap\_height} is the TFM height of \texttt{A} (slot \texttt{0x41})
in \file{mt2mit.tfm}, before conversion to output units.
Where MATH provides only one shift for display and inline superscripts,
the display value is used. Fields with separate display values retain both.
MathLeading uses the median of the em-normalized Latin Modern Math,
STIX Two Math and Cambria Math reference values. These fonts are not
build dependencies.

Source labels: MT-TFM, TFM parameters; MT-STY, package declarations;
MT-PFB, outlines; OT-SUG, OpenType suggested formulas; TeX, the script-space
convention; OT-MIG and MT-MIG, conversion policies. Combined labels indicate
that both source data and an assignment policy contribute.

Values are in font units except the script and radical-degree percentages.
The initial connector overlap is reduced to the nonnegative integer minimum
joining run when required by outline geometry. Both connector ends of
repeatable parts participate; fixed outside ends do not.
