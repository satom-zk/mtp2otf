\section{Overview}

mtp2otf converts the Type~1 fonts and \TeX\ metrics of
MathTime\texttrademark\ Professional~2 (MTPro2) to OpenType MATH.  It
keeps the source designs, including the optical script sizes, and
supplies the layout data used by Unicode math engines.  It contains no
MTPro2 font: each licensee runs it on their own copy of the fonts.

\begin{center}
\begin{tabular}{llll}
\toprule
Edition & Input & OpenType (CFF) & TrueType \\
\midrule
Full & MTPro2 (complete) & \file{MTPro2Math.otf} & \file{MTPro2Math.ttf} \\
Lite & MTPro2 Lite & \file{MTPro2MathLite.otf} &
  \file{MTPro2MathLite.ttf} \\
\bottomrule
\end{tabular}
\end{center}

The OpenType fonts are for Lua\LaTeX, the TrueType fonts for Microsoft
Word on Windows.  Full and Lite have different family names and can be
installed together.  No mtp2otf package is needed to use the fonts:
Unicode characters and OpenType features give access to the designs.
The custom commands of \file{mtpro2.sty} are not provided.  See
\file{mtp2otf-guide.pdf} for using the fonts.

MTPro2 has no upright Roman alphabet.  Upright Latin letters and a few
text symbols come from a Roman font, the \emph{donor}, by default Nimbus
Roman.

The converter was checked with \file{mtpro2.sty} 2009/4/27 v2.3 and its
font definition files 2009/1/30 v2.2; other releases are untested.

Section~\ref{sec:font} describes the font as rules.  Values computed from
the TFM and package files and the donor are not given; the build writes
them to tables (section~\ref{sec:output}).  The detailed rules are in
appendix~\ref{app:rules}, the converter in appendix~\ref{app:converter}
and the tables of the design in the remaining appendices.

\section{Building the fonts}\label{sec:build}

\subsection{Requirements}

\begin{itemize}
\item A POSIX shell.
\item Python 3.10 or later with fontTools.
\item \code{tx} of the Adobe Font Development Kit for OpenType
  (AFDKO).
\end{itemize}

The commands \code{python3} and \code{tx} must be found on
\code{PATH}.  Some installations of AFDKO do not put \code{tx} there;
Debian and Ubuntu, for example, install it in
\file{/usr/libexec/afdko}.  Then add that directory to \code{PATH}:

\begin{verbatim}
PATH="/usr/libexec/afdko:$PATH" ./build.sh
\end{verbatim}

No particular versions are required beyond these.  The versions used
are recorded in \file{build.log}.

\subsection{Inputs}

Create two directories beside \file{build.sh} and put in them:

\begin{description}
\item[\file{mtpro2/}] the PFB and TFM files of MTPro2 and
  \file{mtpro2.sty}.  The Full edition also needs the font definition
  files \file{umt2ms.fd}, \file{umt2mf.fd}, \file{umt2bb.fd} and
  \file{umt2hrb.fd}.  Table~\ref{tab:roles} lists the fonts used; the
  Lite edition uses the 15 fonts of MTPro2 Lite.
\item[\file{donor/}] \file{NimbusRoman-Regular.otf} from the Artifex
  \code{urw-base35} fonts, or nothing if another donor is given with
  \code{-d}.
\end{description}

A donor must be a static (not variable), upright, proportional font of
weight 300 to 599, with the 262 characters of appendix~\ref{app:donor},
each with an outline.  Upright means an italic angle of 0 and neither
the italic nor the oblique flag set.  OpenType (CFF) and TrueType
fonts are accepted; CID-keyed CFF fonts are not.  Besides Nimbus Roman,
TeX Gyre Termes, the URW Times (\code{ztm}) and Monotype Times New
Roman have been tried.

\subsection{Running}

\begin{verbatim}
./build.sh              build the Full edition
./build.sh -l           build the Lite edition
./build.sh -d FILE      use FILE as the donor
./build.sh -h           show the usage
./build.sh -V           show the version
\end{verbatim}

The long forms \code{--lite}, \code{--donor FILE},
\code{--donor=FILE}, \code{--help} and \code{--version} are also
accepted.  A relative donor path is taken from the current directory.

\subsection{Exit status and messages}

\begin{center}
\begin{tabular}{cl}
\toprule
Status & Meaning \\
\midrule
0 & the fonts were built \\
1 & a problem with the inputs or the environment \\
2 & a usage error \\
\bottomrule
\end{tabular}
\end{center}

Errors are written to standard error, starting with \code{build.sh:}.

\subsection{What is checked}\label{sec:preflight}

The build needs every file, glyph and value it uses; it does not make
a partial font.  Before building, it checks, in this order, and
reports everything missing at each stage together:

\begin{enumerate}
\item the command line (exit status 2);
\item \code{python3} (version 3.10 or later), fontTools, \code{tx} and
  the file \file{VERSION};
\item the package files and the donor;
\item the declaration of every font role in the package files;
\item the PFB and TFM files of every role;
\item the contents: every slot the design uses (in the PFB, with its
  encoding and charstring, and in the TFM; for roles with optical
  sizes in all three sizes); the font dimensions used (\file{mt2syt}
  5, 6, 8--15, 17, 22; \file{mt2sys} 5, 18, 19; \file{mt2syf} 5;
  \file{mt2exa} 8--12); the package values of
  section~\ref{sec:package}; and the donor's characters and properties.
\end{enumerate}

A donor that cannot be read as a font, lacks one of the tables
\code{head}, \code{hmtx}, \code{cmap}, \code{OS/2} and \code{post}, has
units per em outside 16--16384, is a variable font or is CID-keyed is
rejected when it is read.

The finished fonts are not checked: if the inputs and the environment
meet these requirements, the fonts are as this document describes.


\subsection{Output}\label{sec:output}

The fonts are written to \file{out/}, each under a temporary name that
then replaces the old file, so a failed build leaves the earlier fonts
intact.  The creation dates in the fonts are the time of the build, or
\code{SOURCE\_DATE\_EPOCH} if set; the same inputs, tools and date give
the same fonts.  Do not run two builds of the same edition at once.

The build also writes \file{build/full/} or \file{build/lite/}, after
the fonts and as a whole, so that its files always belong to the fonts
in \file{out/}:

\begin{center}
\begin{tabularx}{\textwidth}{>{\ttfamily}lX}
\toprule
\normalfont File & Contents \\
\midrule
build.log & version, date, tool versions, SHA-256 of inputs and
  outputs, and a summary of the font \\
constants.tsv & the MATH constants \\
glyphs.tsv & every glyph: code points, source, group, transformation,
  metrics, GDEF class, hinting dictionary \\
variants.tsv & the ready-made sizes of each growing symbol \\
parts.tsv & the parts of each assembly \\
features.tsv & every substitution \\
kerns.tsv & the kerning pairs \\
dictionaries.tsv & the hinting dictionaries \\
\bottomrule
\end{tabularx}
\end{center}

The tables give the values the rules of this document produce from the
user's MTPro2 files.  Their columns are described in
appendix~\ref{app:tables}.  A build of Full takes about 15 seconds and
210\,MB of memory, Lite about 4 seconds and 100\,MB.

\section{The font}\label{sec:font}

Units are thousandths of an em.  A glyph of a source is written
\slot{file}{slot}, as \slot{mt2exa}{64}, or with the role of
table~\ref{tab:roles}, as \slot{exa}{64}.

\subsection{Sources}

text (T), script (S) and scriptscript (SS), each its own PFB and TFM.

Lite, which are identical to those of the complete package.

Besides the fonts, the build reads from \file{mtpro2.sty} and the
\file{.fd} files the script ratios, the skew characters, the math
accents, the font of each optical size, the scale of the extension fonts
and the dimensions of \code{\string\vdots} and \code{\string\ddots}.
The donor gives the 262 characters of appendix~\ref{app:donor} and the
dotless j.  The bold upright letters and digits are MTPro2's own
(\file{mt2mbt}); there is no bold donor.

\subsection{Glyphs}\label{sec:groups}

A glyph that is not meant to change keeps the drawing of its source.
Each glyph belongs to one group:

\begin{center}
\begin{tabularx}{\textwidth}{>{\ttfamily}lX}
\toprule
\normalfont Group & Glyphs \\
\midrule
keep & from a source slot, unchanged \\
scale & from a source slot, scaled about the origin (extension fonts,
  script delimiters) \\
hshift & from a source slot, shifted horizontally (combining accents,
  trimmed horizontal parts) \\
vshift & from a source slot, shifted vertically (sizes centred on the
  axis, parts, script accents) \\
donor & from the donor \\
constructed & new outlines (dots, primes, bars, braces, vector parts)
  and \code{.notdef} \\
empty & spaces \\
\bottomrule
\end{tabularx}
\end{center}

A glyph from a source slot belongs to the first of \code{vshift},
\code{hshift}, \code{scale} and \code{keep} that applies.  Shifts are
rounded only where a rule says so (section~\ref{sec:vshift}); the
OpenType font keeps half units, to 0.01 unit.

The font covers what standard OpenType math uses, not every form, size
and input path of MTPro2.  Some MTPro2 glyphs with a standard
equivalent are left out, such as the fixed wide accents
\code{\string\what}, the raised dots \code{\string\dotup} and
\code{\string\smallint}; so are the bold symbols and the heavy fonts
(appendix~\ref{app:included}).

\subsection{Metrics}\label{sec:metrics}

With $W$ the TFM width and $I$ the italic correction of a glyph that
keeps the box of its source slot:

\begin{center}
\begin{tabular}{llll}
\toprule
Glyph & Advance & Italic correction & Bottom-right kern \\
\midrule
$I = 0$ & $W$ & none & none \\
$I > 0$, role with optical sizes & $W + I$ & none & $-I$ \\
$I > 0$, role without optical sizes & $W + I$ & $I$ & none \\
constructed, donor & own & none & none \\
\bottomrule
\end{tabular}
\end{center}

In a formula \TeX\ adds the italic correction to the width, except
with respect to the position of a subscript \cite[\S543]{tex-program}:
it puts the correction after a character without a subscript
\cite[\S755]{tex-program} and sets a superscript that much to the right
of the subscript \cite[\S756]{tex-program}.  In OpenType this offset
can be given by math kerns at the corners instead of the italic
correction \cite[p.~20]{vieth}.  For the roles with optical sizes, $I$
therefore goes into the advance and the bottom-right kern $-I$ brings
the subscript back, the conversion Hagen and Sundqvist describe for
ConTeXt \cite[\S4.2]{hagen-sundqvist}.  No glyph has both an italic
correction and a math kern; they note that both on one glyph would
cause trouble \cite[\S4]{hagen-sundqvist}.  The roles without optical
sizes are the extension and operator fonts, which hold the big
operators; there $I$ is also kept as italic correction.  OpenType
places the limits of a big operator by it \cite{opentype-math}, and
since almost all engines apply no math kern to big operators, their
scripts depend on the advance and the italic correction, the subscript
moving inwards by $I$ \cite{noto-math}, as in \TeX\
\cite[\S\S749--750]{tex-program}.

The top accent attachment of a source glyph is where \TeX\ centres an
accent \cite[\S738]{tex-program},
\[
  \mathrm{round}\bigl(1000\,(w + i + 2k)/2^{21}\bigr),
\]
with $w$, $i$ the TFM width and italic correction and $k$ the kern with
the skew character.  Combining accents have advance 0 and are placed by
the centre of their \TeX\ box.  \TeX\ raises an accent by the amount
its base exceeds the x-height of the accent's font
\cite[\S738]{tex-program}, which differs between the three sizes;
OpenType has one AccentBaseHeight for all sizes \cite{opentype-math}.
Script and scriptscript accents are therefore lowered by the difference
between their x-height and AccentBaseHeight.

TFM kerns become GPOS kerns.  Appendix~\ref{app:metrics} has the
details.

\subsection{MATH constants}

$s(i)$ is font dimension $i$ of \file{mt2syt.tfm}, $e(i)$ of
\file{mt2exa.tfm}, both in units; $\theta = e(8)$, $x = s(5)$.  The
basis says where each rule comes from:

\begin{description}
\item[TFM] a value from the TFM files of MTPro2: a font dimension, in
  the role \TeX\ gives it \cite[\S\S700--701]{tex-program} and
  Vieth's correspondence assigns \cite[Tables 1--7]{vieth}, or the size
  of characters;
\item[OpenType] the value the OpenType MATH specification suggests
  \cite{opentype-math}, with MTPro2's $\theta$ and $x$;
\item[package] a value of \file{mtpro2.sty};
\item[\TeX] the \code{\string\scriptspace} of plain \TeX, 0.5\,pt
  \cite{plain-tex}, at 10\,pt, which Vieth matches with
  SpaceAfterScript \cite[Table 5]{vieth};
\item[Latin Modern] where OpenType has fewer values than \TeX, the
  choice of Latin Modern Math \cite{lm-math};
\item[conversion] a choice of this conversion.
\end{description}

\TeX\ has three superscript shifts (sup1 $s(13)$ for uncramped display
style, sup2 $s(14)$ for the other uncramped styles, sup3 $s(15)$ for
cramped styles) and two subscript shifts (sub1
$s(16)$ without, sub2 $s(17)$ with a superscript)
\cite[\S700]{tex-program}; OpenType has two and one, SuperscriptShiftUp
answering to sup1 and sup2 and SubscriptShiftDown to sub1 and sub2
\cite[Table 5]{vieth}.  As in Latin Modern Math \cite{lm-math}, sup2,
sup3 and sub2 are used.

For limits, \TeX\ keeps the gap between an upper limit and the operator
at least $e(9)$ and the limit's baseline at least $e(11)$ above it; below,
$e(10)$ and $e(12)$ \cite[\S751]{tex-program}.  The limit and
stretch stack constants follow these roles, as in Vieth's
correspondence \cite[Tables 1--2]{vieth}.  Latin Modern Math 1.959
assigns the two upper values, and the two corresponding stretch stack
values, the other way round.

The specification suggests no value for MathLeading and
DisplayOperatorMinHeight, and suggests 1.5 line heights for
DelimitedSubFormulaMinHeight.  MathLeading is the median of the values
in Latin Modern Math (0.154\,em) \cite{lm-math}, STIX Two Math
(0.150\,em) \cite{stix-two} and Cambria Math (300/2048\,em)
\cite{cambria-math}.  DisplayOperatorMinHeight lies midway
between the largest text operator and the smallest display operator, so
that display style selects the display designs, and
DelimitedSubFormulaMinHeight has the same value.  MinConnectorOverlap
is smaller than every connector length at which two parts join, so
every join can meet it.

\paragraph{Braces.} The default braces are the \emph{morphed} design,

design.  Word cannot switch designs, so the default serves it best.
\feat{cv08} selects Curly with the large sizes, \feat{cv06} straight
braces, which take precedence.

\paragraph{Delimiters in scripts.} \TeX\ tries the normal glyph of the
next larger size before the large sizes.  Each script and scriptscript
delimiter and radical has its own series doing the same: its own glyph,
then the glyphs of the larger optical sizes, enlarged in the font so
that they appear at their own size, then the text series.

\paragraph{Angle brackets and bars.} The sources give the angle brackets
four large sizes and the bars only an assembly.  Three angle sizes are
interpolated between source sizes, and the bars of the seven sizes above
the first are constructed with the top and bottom of the angle bracket
of the same size.  Matching both ends, not only the height, keeps the
choice of size equal in script styles, where Lua\TeX\ rounds height and
depth separately.

\paragraph{Vectors.} The extensible vectors \U{20D7} and \U{20D6} are
assembled from a start, a shaft and the arrow head, keeping the source
glyph's side bearings outside, so the shortest vector is the source
arrow.

\subsection{Hinting and TrueType}

The OpenType fonts keep the hints of the Type~1 fonts: each source's
Private dictionary and each glyph's stems, transformed with the outline.
The CFF is therefore CID-keyed, with a font dictionary for each source
and each scale or vertical shift of it, and subroutinized.  Constructed
glyphs have no hints: there is nothing in the sources to copy for new
shapes, and glyphs put together from several source glyphs were drawn
by \TeX\ as separate glyphs with their own dictionaries.

The TrueType fonts have the same glyphs and tables, with quadratic
outlines and no hints: TrueType hints are programs that move points,
with no correspondence to Type~1 stems and zones.  Their clipping
values (\code{usWinAscent}, \code{usWinDescent}) are constants that work
in Word; the OpenType values, covering every outline, are too large for
Word.  The details are in appendices~\ref{app:vmetrics},
\ref{sec:hints} and~\ref{app:truetype}.

\subsection{Differences from MTPro2 with pdf\LaTeX}\label{sec:differences}

The font follows the Type~1 fonts and \file{mtpro2.sty}; where
OpenType math cannot express \TeX's rules, these differences remain.

\begin{itemize}
\item \emph{Scripts.} A subscript alone is shifted by sub2 rather than
  sub1, so it is lower; superscripts in display style use sup2 rather
  than sup1, so they are lower.  Other styles agree.
\item \emph{Math axis.} The axis of the symbol fonts (font dimension
  22) grows from text to scriptscript size; OpenType has the text value
  for all.  The script outlines
  are kept, so in script and scriptscript style fraction bars and
  delimiter centres are below the minus and equals signs.
\item \emph{Accents.} In script sizes accents over bases lower than the
  x-height are lower than in \TeX.  Accents are raised by the outline of
  the base, not its TFM height, so they are higher over letters whose
  outline exceeds their box, such as the italic A.
\item \emph{Wide accents.} They grow from the ordinary accent, which
  is used over narrow bases; in scripts they shrink with the script
  size.
\item \emph{Limits.} Limits of display-size operators whose TFM box
  exceeds the ink (sum, product) are closer to the operator.
\item \emph{Delimiters.} \code{\string\dbinom} uses a smaller
  parenthesis; stacked fractions get a smaller assembly; bars,
  fixed-size delimiters and radicals differ by a few units.
\item \emph{Engines.} Lua\TeX\ does not apply kerns in script sizes,
  and with the HarfBuzz renderer it does not read the math table.
  Lua\TeX\ does not always use the bottom-right math kern of
  subscripts; using an ordinary letter as an operator changes its
  position; narrow subscripts may change the width of the box.
\item \emph{Word.} The Windows clipping values do not cover the
  largest glyphs; in Word, glyph bottoms were cut only with exact line
  spacing.
\end{itemize}

\subsection{Glyphs and outlines}
\subsubsection{Principle}\label{sec:principle}

A glyph keeps the drawing of its source (section~\ref{sec:groups}) if
its outline has the same geometry: a straight line drawn as a cubic
curve, an open contour closed and a segment of length zero are the
same.  Converting Type~1 to CFF changes no coordinate, advance or hint.

\subsubsection{Which slots}\label{sec:which}

\begin{enumerate}
\item The slot tables (appendix~\ref{app:slots}): for every listed slot
  of a role, the text glyph gets the listed code points, and the same
  slot of the script and scriptscript fonts gives its \feat{ssty}
  forms 1 and 2.
\item Slots used only as outputs of features
  (appendix~\ref{app:features}) are included without code points, in
  all three sizes.
\item From the fonts without optical sizes (\code{exa}, \code{exe},
  \code{exf}, \code{exg}, \code{xl}, \code{xxxl}), the slots used as
  sizes or parts of extensible shapes (section~\ref{sec:stretch}).
\item A slot needed with a different position or as a different step
  of a series gives another glyph from the same slot.  In particular,
  a step that two series follow differently (to a different next size
  or assembly) is copied for the later series, because \TeX\ engines
  give each glyph one next larger size.
\end{enumerate}

Every glyph is reachable from the character map, from a substitution
or from an extensible shape.

\subsubsection{Vertical shifts}\label{sec:vshift}

Glyphs with code points stay where their sources have them.  A glyph
without code points is shifted vertically by one of these rules
(heights after scaling):

\begin{enumerate}
\item \emph{Centred on the math axis}: steps of vertical series taken
  from a font without optical sizes, without code points, other than
  the root, in large operator series (root in an extension font) and in
  delimiter series mixing several extension fonts (the large series of
  \feat{cv07} and \feat{cv08}).  The shift is $\mathrm{AxisHeight} -
  \text{vertical centre}$, rounded, and none if less than 1 in size.
  Delimiter series made only of \file{mt2exa} (brackets, floors and
  ceilings, angles, slashes, radicals, straight and morphed braces)
  keep the position of the source.  This moves the work of placing on
  the axis from the \TeX\ box to the outline and keeps the clipping
  area of the TrueType font small; \TeX\ engines centre these glyphs
  on the axis anyway.
\item \emph{Bottom at 539}: the steps of the Curly overbrace series,
  each step on its own, the parts by one shift for the series.
\item \emph{Bottom at 0}: the parts of vertical assemblies.
\item \emph{Bottom at 569}: the end parts of the normal and Plain
  overbraces, and the middle part using the same shift: the lowest ink
  of the parts made from source slots is put at 569.
\item \emph{Raised by AccentBaseHeight}: the heads of the
  extensible vectors.
\end{enumerate}

The script and scriptscript accents are lowered as described in
section~\ref{sec:accentheight}.

\subsection{Metrics}\label{app:metrics}
\subsubsection{Numbers}

TFM fix-words are read as rational numbers and rounded once, to the
nearest integer, ties to even.

\subsubsection{Advance width and italic correction}

The rules are the table of section~\ref{sec:metrics}.  $W$ and $I$ are
multiplied by the scale of the glyph, and the advance $W + I$ is
rounded after the sum.  The bottom-right kern is one value, without
height steps.  An italic correction of 0 is not recorded.  Constructed
glyphs have the advances of section~\ref{sec:constructed}, donor glyphs
the donor's.  The TFM records of \slot{exa}{182}, 183 and 184 (the
first morphed braces) are broken; those of slots 8, 9 and 176 are used.
Glyphs that change their box (accents, parts, primes) follow their own
rules.

\subsubsection{Top accent attachment}

For a glyph from a source slot, with $w$ and $i$ the width and italic
correction in TFM units ($2^{20}$ per em) and $k$ its kern with the
skew character (0 if none):
\[
  \mathrm{TopAccent} = \mathrm{round}\Bigl(1000\cdot
    \frac{w + i + 2k}{2\cdot2^{20}}\Bigr).
\]
The skew character is that declared for the source file (an \file{.fd}
shape declaration before the family declaration).  The value is not
recomputed after the advance becomes $W + I$.  Every glyph that keeps
the box of its slot has it; donor glyphs and spaces have none.  Other
rules come first:
\begin{enumerate}
\item combining accents (below);
\item the primes (section~\ref{sec:constructed});
\item parts and glyphs with changed outline or advance: none, or half
  the advance;
\item glyphs of zero TFM width that are not combining accents (the
  negation slash \U{0338}): the horizontal centre of the ink.
\end{enumerate}

\subsubsection{Combining accents}

As in \TeX, the centre of the accent's box (its TFM width $W$) is
placed at the attachment point.  The rule applies to the slots that
\file{mtpro2.sty} declares with \code{\string\DeclareMathAccent} in the
symbols family and whose text glyph has a code point of general
category Mn (13 accents, and slot 78 also for \U{0305}), in all three
sizes.  They have advance 0, and
\[
  \mathrm{TopAccent} = C = -\bigl(\mathrm{AxisHeight} +
  \mathrm{round}(\theta/4)\bigr)
\]
in every size, $\theta$ being the default rule thickness
($e(8)$; the rounding takes ties to even).  The
outline is shifted by $C - W/2$, with $W$ the rounded TFM width of the
size and $W/2$ not rounded.  $C$ is a convention of the font's
coordinates; it cancels in the final position.  Accents with a positive
advance (\code{\string\wbar}, \code{\string\wwbar}) have TopAccent at
half the advance.

\subsubsection{Vertical position of script accents}\label{sec:accentheight}

OpenType math raises an accent by the amount the outline of the base
exceeds AccentBaseHeight, one value for all sizes.  \TeX\ uses the
x-height of the accent's font (font dimension 5), which grows from the
text to the scriptscript symbol font.  The script and scriptscript
accents are therefore moved down by the difference:
$dy = -(\text{x-height of the size} - \mathrm{AccentBaseHeight})$,
x-height being font dimension 5 of \file{mt2sys} and \file{mt2syf}.

This applies to the S and SS glyphs of the slots declared with
\code{\string\DeclareMathAccent} in the symbols family (including
\code{\string\wbar} and \code{\string\wwbar}), 18 in each size: 15 from
the source fonts, the copy for \U{0305}, the extensible part of the
overline and the mirrored \U{20D6}.  The shift is applied once.  It does
not apply to the parts of the extensible vectors (rule~5 of
section~\ref{sec:vshift}), the negation slash or the tie, nor to the
text size.

\subsubsection{Kerning}

The TFM kerns are copied to GPOS \feat{kern}, without adding or
removing italic corrections.  Pairs with the skew character on the
right are left out.  Every glyph made from a slot gets the kerns of that
slot.  Ligature and boundary programs are not supported; a TFM with
them is an input error.

\subsection{Growing symbols}\label{app:growing}
\subsubsection{Series}

\begin{itemize}
\item 27 large operators, each with six sizes (text, display, xl, XL,
  XXL, XXXL) and no assembly.
\item Parentheses and braces: a normal series of five sizes and an
  assembly; with \feat{cv07} and \feat{cv08} a large series of 23 sizes
  and an assembly, whose roots are separate glyphs in each optical
  size.
\item Brackets, floors, ceilings and slashes: five sizes.  Angle
  brackets, bars and double bars: eight sizes.  The bars have
  constructed steps, and the angle brackets constructed steps of
  heights 1100, 1450 and 2100 (section~\ref{sec:constructed}).
\item Horizontal: hat (37 sizes), tilde (37), check (35), over
  parenthesis (24 and an assembly), braces (35 and an assembly), six
  relation arrows, the vectors and the overline.
\end{itemize}

The steps follow the TFM chains of next larger characters and the
extensible recipes.  Steps beyond them (the xl and xxxl operators, the
large series of \file{exe}, \file{exf} and \file{exg}, constructed
steps) and the morphed braces are given explicitly.

\subsubsection{Braces}

The default vertical braces are the \emph{morphed} design: left
\slot{exa}{182}, 184, 186, 188, right 183, 185, 187, 189, then the
assembly (section~\ref{sec:stretch}).  The Curly series of
\file{mtpro2.sty} starts at 8, 110, 26, 40.  The TFM chain of
the morphed braces is broken (182 leads nowhere and 183 to the left
assembly), so it is not followed.

\subsubsection{Delimiters in script sizes}

Each S and SS glyph of a vertical delimiter or radical (not of the
large operators) is the root of its own series
(section~\ref{sec:stretch}):
\begin{itemize}
\item S: the S glyph; the T glyph scaled by $1/r_1$; the steps of the
  T series larger than that; the T assembly.
\item SS: the SS glyph; the S glyph scaled by $r_1/r_2$; the T glyph
  scaled by $1/r_2$; the larger T steps; the T assembly.
\end{itemize}
$r_1$ and $r_2$ are ScriptPercentScaleDown and
ScriptScriptPercentScaleDown as fractions.  A step is larger if its
AdvanceMeasurement exceeds that of the step before.  The scaled glyphs
are new glyphs, three per root, shared by roots with the same outline;
their advances are rounded, their coordinates not.

\subsubsection{Extensible vectors}

The vectors \U{20D7} and \U{20D6} keep, outside the assembled arrow,
the side bearings of the source glyphs.  For each size, $b$ is the left
side bearing of the minus sign (slot 0), $W$ the TFM width of the right
arrow (slot 33), $r$ its right side bearing, $R$ the ink width of its
head and $C$ the length of the shaft: the smaller of the ink width of
the minus sign and the distance from the left of the ink of the arrow
to its leftmost point outside the shaft's vertical range.

\begin{center}
\begin{tabular}{lllll}
\toprule
Part & Outline & Advance & Connectors & Extender \\
\midrule
start & the shaft rectangle moved right by $b$ & $b + C$ & 0, $C$ & no \\
shaft & a rectangle of width $C$ & $C$ & $C$, $C$ & yes \\
head & the ink of the arrow, left at 0 & $R + r$ & measured, 0 & no \\
\bottomrule
\end{tabular}
\end{center}

All parts are raised by AccentBaseHeight
from the position of the source.  The shortest assembly is
$b + R + r = W$.  The only ready-made size is the root.  \U{20D6} is the
mirror image, with parts head, shaft, start; the shaft is shared.

\subsubsection{Values}

\begin{itemize}
\item \emph{AdvanceMeasurement} of a size: the ink length in the
  direction of growth, rounded down, plus 1; for the vectors and the
  overline, the ink width rounded up.
\item \emph{FullAdvance} of a part: vertically the ink height,
  rounded; horizontally the advance.
\item Vertical parts have their ink bottom at 0 and keep their
  horizontal position and advance.  The part slots are those of the
  TFM extensible recipes.
\item Horizontal parts are trimmed on the joining side: a part joining
  on the left has its ink moved to start at 0; a part joining on the
  right has its advance set to the right of its ink.  The outer side
  keeps the source's bearing.
\item \emph{Connector lengths}: equal to FullAdvance for extenders; 0 at
  the outer ends of an assembly; otherwise measured from the outline.
  The outline's extent along the direction of growth is divided into
  64 strips; in each, at its middle, the minimum and maximum across
  the direction are taken (curves approximated by 8 line segments).
  Counting from the joining end, the strips whose minimum and maximum
  stay within 8 units of those of the end strip are counted; the
  length is that number times the strip length, rounded down.
\item The horizontal braces (over, under, Plain, Curly) also limit the
  inner connectors to the extender's thickness less 8: the extender is
  as high as the TFM height of \slot{exa}{130}.
\item Assemblies have italic correction 0.
\item \emph{ExtendedShapeCoverage}: the steps without code points of
  vertical series other than roots, the parts of vertical assemblies,
  and the nine text integrals \U{222B}--\U{2233}.
\end{itemize}

\subsection{Character set}

\begin{itemize}
\item The character map has formats 4 and 12, for platforms 0 and 3.
  Private code points are \U{E000}--\U{E284}
  (appendix~\ref{app:pua}).
\item The slot tables are in appendix~\ref{app:slots}; 77 groups of code
  points share a glyph, such as Latin and Greek capitals of the same
  form.  The symbols slot 15 is both \U{2219} and \U{2022}, slot 63
  both \U{22A5} and \U{27C2}, so that the commands of
  \code{unicode-math} for these symbols all find a glyph.
\item Spaces have the widths of Unicode
  (appendix~\ref{app:constructed}); the figure space \U{2007} is as wide
  as the digits and the punctuation space \U{2008} as the period.
\end{itemize}

\subsection{Layout}\label{app:layout}

\subsubsection{Selectors and features}

Full has \feat{cv01}--\feat{cv19} and \feat{ss01}--\feat{ss10}, Lite
\feat{cv01}--\feat{cv09}, \feat{ss07} and \feat{ss10}, with the same

alternatives are fixed.  Besides them: \feat{ssty} (two alternates),

The names of the selectors are in appendix~\ref{app:features}.

Substitutions are given for text glyphs; when both input and output
have script and scriptscript forms, the same substitution is made
between those forms.

\subsubsection{Order}

One lookup per feature, in this order: \feat{ccmp}, \feat{cv01} to
\feat{cv19}, \feat{ss01} to \feat{ss10}, \feat{dtls}, \feat{ssty}.
Exchanging any two of the following changes results, so they keep this
order: \feat{ss01} before \feat{ss02}, \feat{ss03} before \feat{dtls},
\feat{cv18} and \feat{cv19} before \feat{ssty}.

\subsubsection{GPOS and GDEF}

GPOS has only \feat{kern}.  GDEF classes: marks (class 3) are the
glyphs with a code point of general category Mn, \code{\string\wbar}
and \code{\string\wwbar}, and their S and SS forms; all other
glyphs are base glyphs (class 1).  All lookups have flag 0.

\subsection{Glyph names and order}\label{sec:names}

Glyph names exist only in the design and the converter; neither font
contains them.  A name is a base name and suffixes.

\begin{itemize}
\item Base: \code{uniXXXX} or \code{uXXXXX} from the primary code
  point (the smallest non-private code point, or the private one if
  there is no other).  A glyph without code points takes the base of
  the glyph it is reached from (the one with the smallest primary code
  point if several); a step copy the name of its series' root with the
  step; a part the name of the first root using it.
\item Suffixes, in order: the features reaching the glyph (fewest
  features, then the first tag in alphabetical order; an alternate
  adds its number, as \code{.cv09.2}); the step (\code{.v1}, \dots,
  \code{.h1}, \dots); the part (\code{.bot}, \code{.ext}, \code{.mid},
  \code{.top}, \code{.left}, \code{.right}); the size (\code{.s},
  \code{.ss}).
\end{itemize}

Order: \code{.notdef}; glyphs with code points by primary code point;
glyphs without, by the primary code point of their base and then by
suffix.

\subsection{TrueType}\label{app:truetype}

Outlines are converted to quadratic curves within 0.6 unit and their
direction reversed; coordinates are integers.  Left side bearings are
the left of the ink; \code{maxp} has one zone; \code{post} is format~3.

\subsection{Constructed glyphs}\label{sec:constructed}

Dimensions come from the sources: a point is the design size of
\file{mt2syt}, a mu 1/18 of its quad (font dimension 6), both rounded
to units.  The constructions are listed in
appendix~\ref{app:constructed}.

\begin{description}
\item[Primes] \U{2032}--\U{2034}, \U{2057}, \U{2035}: the S glyph
  scaled by the script ratio and raised by sup1 (\file{mt2syt}
  dimension 13), repeated at $0.7W$.  The S and SS forms repeat the S
  and SS glyphs at $W$ (one prime is the source glyph).  TopAccent of

\item[Dotless j] \U{0237}: see the donor.
\item[Rows] the horizontal braces \U{23DE}, \U{23DF}, the Plain braces
  and their middles, the XXXL conjunction: source glyphs side by side.
\item[Spaced dots] \U{2026} (\slot{mi}{58}), \U{22EF}
  (\code{\string\cdotp}, \slot{sy}{1}), \U{2237} (\slot{sy}{87}): dots
  with a thin space (3\,mu) between; the advance is the sum.
\item[Vertical dots] \U{22EE}: as \code{\string\vdots} of
  \file{mtpro2.sty}, three dots its \code{\string\baselineskip} apart,
  centred on the axis; the advance of one dot.
\item[Diagonal dots] \U{22F1}, \U{22F0}: as \code{\string\ddots} of
  \file{mtpro2.sty}, three dots raised by its three

\item[Moustaches] \U{23B0}, \U{23B1}: the bottom and top parts of the

\item[Brace extender] a rectangle 200 wide and as high as the TFM height

\item[Mirrors] \U{20D6} and the left vector parts: about TopAccent if

\item[Bars] the steps of \U{007C} and \U{2016}: rectangles in the

\item[Interpolated angles] the steps 1100, 1450 and 2100 of the angle
  brackets: the neighbouring steps interpolated by height, centred on

\item[Vector parts] see section~\ref{sec:stretch}.
\item[Over parenthesis parts] the parts of the assembly of \U{23DC},
  cut from \slot{exa}{194}.
\end{description}

\section{The converter}\label{app:converter}

\subsection{Processing}

\begin{enumerate}
\setcounter{enumi}{-1}
\item \file{build.sh} reads the command line and checks the
  environment, then runs\\ \code{python3 tools/mtp2otf.py full|lite
  DONOR} with the absolute path of the donor.
\item The design data (section~\ref{sec:data}) is read and checked.
\item Check: the package files and the donor.
\item The package files are read; the role declarations give the font
  files and scales.
\item Check: the PFB and TFM files.
\item The sources are read: Type~1 through \code{tx -cff +b}
  (appendix~\ref{sec:principle}).
\item The \code{chain} entries of the series are expanded along the TFM
  chains.
\item Check: the contents.
\item The font plan is made; the OpenType and TrueType fonts are
  written; the CFF is subroutinized.
\item The log and the tables are written to \file{build/full/} or
  \file{build/lite/} (section~\ref{sec:output}).
\end{enumerate}

\subsubsection{Subroutinization}

The OpenType font is written without subroutines to a temporary
directory, and \code{tx -cff +S +b} makes the CFF table that replaces
it.  \code{tx} rewrites the Private dictionaries: it chooses
\code{defaultWidthX} and \code{nominalWidthX}, rounds reals to 0.01 and
may reorder stem widths.  The converter checks that the glyph order and
each glyph's dictionary are unchanged and restores every dictionary
value except \code{defaultWidthX}, \code{nominalWidthX} and
\code{Subrs}.  It writes \code{FDSelect} in format 3: \code{tx} writes
format 4, defined only for CFF2, when there are more than 256 ranges,
as this font has.

Section~\ref{sec:font} gives the rules of the font; the values the rules
give depend on the TFM files, the package files and the donor.  The
build writes them to tab-separated tables, as the plan of the font has
them:

\midrule

The files are UTF-8 with LF line ends.  The first line names the
columns; an empty field means no value.  Glyphs are named as in
section~\ref{sec:names}.  A slot is written \code{file:slot}, such as
\code{mt2syt:69}, with the file name, so the script and scriptscript
fonts are told apart.  Integers are written as such; other values in the
shortest decimal that reads back as the same value (such as
\code{-480.5}); scale factors as ratios (\code{10/7}).

\begin{description}
\item[\file{glyphs.tsv}] \code{codepoints}: hexadecimal, ascending,
  separated by spaces.  \code{source}: where the outline comes from:
  a slot, \code{donor:U+0041} or \code{constructed:} and the name of
  the construction (appendix~\ref{app:constructed}); empty for spaces
  and \code{.notdef}.  \code{group}: \code{keep}, \code{scale},
  \code{hshift}, \code{vshift}, \code{donor}, \code{constructed} or
  \code{empty} (section~\ref{sec:groups}).  \code{scale}, \code{dx},
  \code{dy}: the scaling about the origin and the following shift
  applied to the source outline; for the donor, the scale converts its
  units per em.  \code{italic}: the MATH italic correction;
  \code{math\_kern}: the bottom-right math kern; \code{top\_accent}:
  the top accent attachment.  \code{class}: the GDEF class, 1 or 3.
  \code{extended}: \code{yes} if in ExtendedShapeCoverage.
  \code{dictionary}: the number of the font dictionary.
\item[\file{variants.tsv}] \code{step} counts the sizes from 0 in the
  order of the MATH table; the first size need not be the root itself.
  \code{measurement} is the AdvanceMeasurement.  Roots with an assembly
  only appear in \file{parts.tsv} alone.
\item[\file{parts.tsv}] \code{index} counts from 0; \code{extender} is
  \code{yes} for an extender; \code{start} and \code{end} are the
  connector lengths and \code{full} the FullAdvance.
\item[\file{features.tsv}] the inputs of a ligature and the outputs of
  an alternate substitution are separated by spaces.
\item[\file{dictionaries.tsv}] \code{source} is the source file
  (\code{donor} for the donor's dictionary), \code{scale} and \code{dy}
  the transformation the dictionary was made for
  (section~\ref{sec:hints}).  Arrays are separated by spaces.
  Dictionary 0 is the empty dictionary of glyphs without hints and has
  one line.  \code{defaultWidthX}, \code{nominalWidthX} and \code{Subrs}
  are left out: subroutinization chooses them.
\end{description}

The tables are not read back from the fonts.  In the OpenType font the
coordinates are rounded to 0.01 unit (section~\ref{sec:groups}) and
BlueScale to the precision of a CFF real number; every other value is
the same.
